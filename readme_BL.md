# PrimerDesigner Pro: актуальная схема работы

## Архитектура

- Расширение Chrome выбирает режим расчёта автоматически.
- Онлайн-расчёт: `popup` -> Django (`/api/design/`) -> микросервис Primer3 (`/api/design/`).
- Оффлайн-расчёт: локальный эвристический движок в расширении.
- Django теперь работает как прокси и health-check слой.
- Микросервис Primer3 делает расчёт, кэширует повторные запросы (in-memory TTL), отдает health.

## Что изменилось после оптимизации

- Добавлен мастер установки в `Настройки`:
  - `✨ Установить автоматически` (подбирает метод и подготавливает установщик),
  - `✅ Проверить установку`,
  - `⏰ Напомнить позже`.
- После успешной проверки сервиса расширение автоматически отключает `Принудительно оффлайн`.
- При недоступности сервера всегда срабатывает fallback на локальный режим.

## Важно про установку

- Вводить вручную `curl -sSL ... | bash` больше не обязательно.
- На Linux/macOS мастер скачивает скрипт-установщик, который нужно запустить в терминале.
- На Windows мастер подготавливает `ps1`-установщик.

## Проверка работоспособности

1. Запустить backend + микросервис:
   - `docker compose up -d backend primer3-service`
2. Проверить backend health:
   - `http://localhost:8000/api/health/`
3. Проверить микросервис напрямую:
   - `http://localhost:8001/health`
4. В расширении нажать `✅ Проверить установку` и убедиться, что режим переключился на серверный.

## Текущие ограничения

- WASM-путь пока подготовлен на уровне UI/логики fallback, но полноценный `primer3.wasm` ещё не интегрирован.
- Кэш микросервиса хранится в памяти контейнера и очищается при перезапуске.
